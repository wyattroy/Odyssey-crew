<objective>
Make the board the play surface (UI-SPEC §Layout items 4-5, §Build order 3): render Dare/Abide/Give (and the eat satchel/hold choice) as large clickable affordances on the board at every human decision point, wired to the EXISTING commit path, and surface the current scene beat's story text in a prominent on-board narration area.

Purpose: This turns the board from a read-only projection into the primary play surface without forking the engine. The single hard rule (Architecture (c), Pitfall 2/5): the clickable verbs must reuse the existing `promptButtons()`/`ctrl-<id>`/`askResolve()` Promise seam — the board is that same input path re-hosted visually, never a second path that sets `p.commit` or touches bot logic. Narration must render the same event stream the log already carries (Pitfall 3), not a forked second copy.

Output: A board where a human clicks Dare/Abide/Give (and satchel/hold) directly on the board and the game advances identically to the current prompt path, with the current beat's story text shown prominently on the board.
</objective>

<artifacts_this_phase_produces>

- **Re-hosted control slots:** the existing per-seat `ctrl-<id>` slots (populated by `promptButtons()` when `seatId!=null && !directorMode`) are placed inside the board's crew/action layout so the verb buttons and eat choices appear ON the board. No new input widget, no new Promise plumbing.
- **New function:** `renderNarration()` — a prominent "current beat" area showing the latest beat's `tell` sentence in its `cls` colour; composed into `renderBoard()`.
- **New CSS classes** in the existing `<style>` block: action-bar layout for the large Dare/Abide/Give buttons (reusing the existing `.dare`/`.abide`/`.give` accent classes) and a narration-surface class, all in the shipped palette.
- **Optional `_`-transient:** `state._narration = {html, cls}` set by the reducer at the existing `log(n.html, cls)` call in the reveal loop and cleared per phase (clearBones-style), if reading "the current beat tell" straight from the last log entry proves ambiguous (BOARD-07).
